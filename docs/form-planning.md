# 表单规划主流程

首页填写需求 → 真实阶段时间线 → 自动打开攻略 → 修改条件生成新版本。

## 输入与版本

- 核心条件包含出发地、目的地、日期（可留空）、天数、人数、预算和偏好。
- 更多需求包含预算口径与包含范围、旅行节奏、交通、行动及饮食需求。日期按北京时间检查；未知日期传 null，不伪造天气和车次。
- 预算选项按范围上限作为约束；默认人均人民币，切换全员后直接使用填写金额，不重复乘人数。
- 新旅行生成独立会话。已有攻略和攻略库的调整入口回填当前旅行条件，生成成功保存新版本；旧方案、证据快照和导出保持独立。
- 首页表单按人民币规划；历史非人民币方案继续使用原对话调整，不静默转换金额或币种。
- 复杂需求仍可进入辅助对话。表单修改沿用已有预订保护，不允许静默清除已有预订。

## 接口与进度

复用 `POST /chat/stream`（以及原同步 `/chat`），增加可选的 `planning_requirements` 对象，遵循 `PlanningRequirements`，与 `interaction_response` 互斥。保留 `message` 作为可读摘要；规划读取结构化条件，跳过模型需求提取，继续使用原取证、校验和版本保存流程。原聊天和 CLI 请求保持兼容。

SSE status 事件增加可选 `stage` 和 `state`（running/completed/failed）。现有客户端仍可只读取 text/sources。页面将真实节点归入六个阶段：需求整理、资料查找、地点筛选、每日编排、预算与时间检查、保存攻略。自动修订会重新显示编排及后续步骤，不采用虚构百分比。

刷新沿用现有后台执行和历史轮询。浏览器保存本次条件及预期新版本号，用于恢复表单和判断是否应打开新攻略，不把旧版当作本次成功。禁用本地存储时，生成和保存仍有效，刷新后自动恢复表单流程不保证可用，可从“我的旅行”或“我的攻略”查看结果。

规划失败显示原因和“修改条件后重新规划”；阻塞修订不携带旧版本成功标志。成功自动打开 `/sessions/{session_id}/plans/{version}`。

## 等待页样式

等待页沿用首页山水素材、奶油白底和墨绿字体，以橙色标记正在执行的阶段。桌面为步骤链与攻略预览双栏，手机改为上下排列，减少动态效果偏好时停止光晕动画。

旅行摘要和“查看旅行需求”弹窗读取本次提交或恢复的条件快照。右侧展示已有目的地参考图，未覆盖的目的地使用中性意境素材；每日卡片仅为生成中的预览，不提前展示未经确认的景点、费用或时间。失败时同步更新标题、预览状态与重试入口。

## 验证

后端回归覆盖结构化条件精确传递、跳过提取模型、阶段事件、旧版不可变、失败保留旧方案和输入边界。前端回归覆盖日期未定、预算口径、阶段状态和修订回退。

本地离线浏览器验收使用真实 HTTP/SSE、模拟规划模型及独立数据库，检查刷新恢复、自动打开攻略、条件回填、失败重试、新旅行隔离和桌面/390px/320px布局；不代表真实模型或第三方查询的成功率与耗时。
