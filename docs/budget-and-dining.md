# 预算保存与每日三餐

## 预算

在预算明细中编辑金额、勾选计入状态及全员预算上限后，点击「保存预算」。保存前会提示修改尚未保存；保存成功后，同账号再次打开该版本或从其他设备查看时读取相同内容。PDF、Markdown 和 HTML 导出均包含已保存预算，金额标为用户填写，不作为实时商家报价。保存失败保留输入，多页面同时修改通过修订号返回冲突，不覆盖其他页面已保存内容。

数据与行前清单采用相同模式：会话 `budget_lists` 与独立攻略 `guide_versions.budget` 保存版本状态，金额使用整数分，未知金额为 null，不能当作免费。保存只修改预算，不自动改写原始行程、生成约束或查询证据。版本之间互不覆盖；删除聊天后独立攻略的预算仍保留。「恢复方案金额」恢复原生成值，之后需要再次点击保存。

启动时为旧 `guide_versions` 表补上可空的 `budget` 列，保留既有内容。新接口沿用账号归属检查及写请求的同源检查。保存校验金额范围、整数分、完整项目集合和重复编号。

离线 HTML 的预算可以保存到当前浏览器，和在线账号分别保存，不自动回传账号或修改已下载的文件。清理浏览器数据会丢失该离线修改。

## 每日三餐与布局

新生成攻略要求每天分别推荐早餐、午餐、晚餐，填写对应天数和餐次。食品列表上限调整为 120，覆盖最长 30 天的三餐和额外小吃。模型遗漏时补齐基础用餐建议，标明这是补充建议，保留忌口及首末日到离时间的弹性，不编门店、营业时间或价格。旧版缺失的餐次也会在美食页补充展示。补齐过程不会再次给餐食加预算或重复加入行程收费项目。

路线摘要回到正常文档流，不再绝对定位在餐食卡片上方。美食和预算页面按自身容器宽度适配，兼容攻略库右侧版本栏；长路线换行、天数标签横向滚动，点单提醒在窄列移到正文下方。

## 验证

`tests/test_budget.py` 验证跨入口同步、刷新与重启、删除聊天后保留、恢复会话、按版本隔离、导出、修订冲突、金额与项目校验、账号隔离及旧表迁移。三餐用例覆盖 30 天、饮食限制、空攻略与长路线。

本地 Chromium 使用独立测试数据库、模拟方案和超长交通文字，在 1536、1440、1024、820、390px 宽度检查路线与餐食不重叠、三餐标签齐全、无页面横向溢出，并验证预算保存后刷新恢复。截图位于 `output/my-guides-ui/implemented/`。

本轮完整 Python 回归 253 项通过，前端测试 46 项通过；未调用付费模型或实际旅游接口，未修改原有用户数据库。
