# 我的攻略

入口为首页导航中的「我的攻略」，地址 `/guides`。页面沿用暖白、墨绿、青绿与暖橙配色；电脑端使用照片卡片网格与侧栏，手机端使用单列卡片。卡片封面复用本地旅行意境图，不代表真实照片。

## 已实现

- 完整方案生成并持久化成功后自动入库；失败草稿不会替换上一版攻略。普通问答不入库。
- 一次规划会话对应一份攻略，默认展示最新版本，历史版本在详情页切换。
- 搜索名称或目的地、收藏与收藏筛选、按更新时间或出发日期排序、重命名与删除。
- 详情复用现有七个板块，支持 PDF、Markdown、内嵌图片的离线 HTML 导出。
- 「继续调整」打开原会话；原聊天已删除时，从独立保存的方案恢复上下文和版本，新生成结果接着原版本号保存。
- 删除聊天保留攻略；删除攻略及全部版本保留聊天。清除攻略后，旧会话不会在重启时自动恢复已删除的版本；后续成功生成的新版本可以再次入库。
- 行前清单在攻略库和原攻略页之间同步，按版本隔离，并保留修订号冲突检查。删除聊天后仍可在线编辑独立攻略的清单。
- 查看、搜索、收藏、重命名、恢复会话和导出不消耗生成额度；发送新的聊天请求仍按原额度规则扣除。

## 数据与兼容

继续使用 `DATABASE_PATH` 所指向的 SQLite，无需新数据库服务或依赖。

`guide_library` 保存用户归属、来源会话、卡片摘要、收藏及最新版本号。`guide_versions` 保存结构化方案、生成时的公开攻略快照、证据快照与独立清单。文件按需导出，不提前存三份重复的 HTML/PDF/Markdown。

启动时自动补入已有会话中的方案，按来源会话及版本去重。账号模式只迁移有明确账号归属的会话，未归属的本地/CLI 会话不会分配给网页用户。启动迁移当前扫描检查点历史，适用于现有小范围邀请体验；数据规模明显增大时应增加迁移游标。

个别无法解析的历史记录会保留原数据、跳过导入并记入服务日志，不阻止其他攻略迁移或服务启动。

重命名修改攻略库中的显示名称，原始版本及导出正文标题保留生成时内容。清单是可编辑状态，会反映到之后的导出。预算金额、计入状态及预算上限修改后自动保存，按账号和版本持久化，并反映到再次查看和导出中；原始行程估算不改写。打开旧攻略不会重新请求模型或联网刷新票价、天气与开放时间。

所有攻略内容、版本、导出及修改接口在服务端校验账号归属。数据库必须放在持久化目录并备份；不要将其放入静态文件目录。升级前建议使用 SQLite backup API 备份既有数据库。

## 验证

`tests/test_library.py` 覆盖生成与流式保存、版本不覆盖、删除聊天后保留、重启恢复、继续调整、旧数据迁移、重复同步、收藏重命名、删除防复现、清单跨入口同步、导出、失败修订及跨账号访问拒绝。

完成 249 项 Python 全量回归、46 项前端测试；最后的中断恢复修正另通过 7 项攻略库回归。使用独立 SQLite、模拟模型和本地 Chromium 验收桌面 1440px / 手机 390px 页面，覆盖搜索、收藏、版本切换、清单刷新保留与继续调整，无脚本错误和手机横向溢出。实装截图位于 `output/my-guides-ui/implemented/`。未调用真实模型或外部旅游接口，也未修改开发者原有数据库。
