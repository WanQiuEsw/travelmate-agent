# 本地演示：小红书优先、百炼补充

小红书按“特色美食、地方小吃、点单推荐”和“旅游避坑、排队、消费陷阱、替代方案”分别检索，并带入饮食要求与旅行偏好，再结合现有知识库（支持百炼）整理到攻略的美食与避坑栏目。未配置或不可用时使用知识库补充；价格、开放时间、预约、天气和车次继续走原有独立核实流程。这里的录入是保存到攻略版本，不自动写入百炼知识库。

## 配置

本地需要安装 Node.js 20 或更新版本，并确保 `node --version` 可运行。签名通过固定版本的 TripStar JS 引擎生成，只使用 Node 内置依赖，无需 `npm install`；Python 不再使用 `xhshow`。

```powershell
uv sync --all-extras
```

在项目根目录 `.env` 中配置：

```dotenv
KNOWLEDGE_PROVIDER=aliyun
# 保留已有的 ALIBABA_CLOUD_*、ALIYUN_WORKSPACE_ID、ALIYUN_INDEX_ID 配置
XHS_ENABLED=true
XHS_COOKIE="填入网页端登录后的 Cookie"
```

获取 Cookie：自己在浏览器中登录小红书网页，打开开发者工具的 Network 面板，搜索一次旅游攻略，选择发往 `edith.xiaohongshu.com` 的请求，复制 Request Headers 中的 Cookie 值。必须包含 `a1` 和 `web_session`，建议复制完整值。也支持浏览器导出的 Cookie JSON 数组。

Cookie 只放在本地 `.env`，不要发到聊天、截图或提交到 Git。无需提供账号密码。遇到登录失效或访问限制，先在浏览器正常登录、确认网页可用，再更新 Cookie；程序不会自动解验证码或反复重试。

## 先单独检查数据入口

```powershell
uv run --all-extras python -m travelmate.xhs 杭州
```

此命令只调用小红书，不调用大模型或百炼。成功时打印笔记正文、公开链接、发布时间和新鲜度；空结果也会明确返回。

常见错误：`not_configured` 未配置或已关闭；`invalid_cookie` 缺少必要 Cookie；`missing_node` 找不到 Node.js；`login_or_risk_control` 登录态失效或平台限制；`session_blocked` 此 Cookie 已在本进程被拒绝，后续调用不再联网；`search_unavailable` 网络或响应异常；`signing_failed` 签名引擎执行失败。不要将这些错误解释成“该城市没有攻略”。

响应中的 `diagnostic` 只保留 `stage`（search/detail）、`http_status` 和数字型 `api_code`，不返回平台原始消息、Cookie 或签名。这样可以区分搜索和详情失败，而不泄露凭证。

一旦遇到登录或风控拒绝，本进程立即停止该 Cookie 的后续请求，不重试、不自动切换签名。先在浏览器确认账号状态，再人工处理；不要反复重启程序尝试同一 Cookie。更换 Cookie 后可重新调用。此保护只覆盖单进程，独立 CLI 调用和服务重启不会共享拦截状态。

请求明确禁用 `HTTP_PROXY`、`HTTPS_PROXY` 等环境代理，保持与 TripStar 的直连行为一致。签名在本地子进程执行，仅通过 stdin 传入路径、请求体和 a1，不把 Cookie 放进命令行参数。其他 Cookie 仅用于发往小红书的 HTTP 请求。

## 启动完整演示

```powershell
uv run --all-extras uvicorn travelmate.api:app --host 127.0.0.1 --port 8000
```

本地 HTTP 沿用 `AUTH_COOKIE_SECURE=false` 和现有邀请码登录流程。改 `.env` 后重启服务。

示例需求：从上海出发，两个人，2026年12月1日去杭州一天，总预算1000元，包含全部费用，喜欢西湖和当地美食，少走路。先确认日期和预算口径，再生成攻略。

进度会显示小红书检索及知识库补充。攻略“参考来源”保留小红书笔记链接和发布时间，HTML、Markdown 与 PDF 沿用同一份来源数据。没有 Cookie 时仍可用百炼生成攻略，但这不代表小红书接入验证成功。

## 当前范围

- 每个主题一个最新排序的搜索页，每页最多取前8个搜索条目中的4篇笔记正文，每主题网络时间预算约18秒，不自动重试；任一主题出错后停止后续主题，转知识库补充。
- 优先采用近30天；近30天有效结果少于2篇时保留近90天内容。发布时间未知会明确标记，超过90天的笔记不使用。
- 按城市和现有主题覆盖规则过滤，资料不全时补知识库；知识库仍缺少的主题继续联网检索。
- 发布时间、更新时间、查询时间分开记录；不能保证覆盖全站最新笔记。来源链接可能要求登录，小红书也可能限制直接打开。
- 行程概览仅显示去重后的核心游玩地点，过滤抵达、用餐、入住与返程等安排。预览切换到景点时，去掉括号内行程说明和常见景区后缀，以“目的地 + 核心地名 + 建筑街景 / 风光全景”综合排序搜索配图；优先选取标题匹配、风景相关的图片，过滤明确的人像、探店及拼图标题，优先使用高清图。每次只搜索一次，最多尝试3个候选媒体地址，不抓详情；标题和尺寸筛选不能保证图片实际内容一定符合景点。
- 图片由后端即时下载并在进程内缓存6小时，未找到图片缓存10分钟；最多32项、每张不超过3MB，只允许小红书图片域名，下载媒体时不发送登录 Cookie。图片搜索与正文搜索共享风控停止机制。未匹配或加载失败时显示默认示意图，默认图也不可用时显示空图提示。
- 美食卡片进入可见区域时，串行按“城市 + 菜名 + 美食 菜品 实拍”搜索；标题须含菜名，排除风景、街景、航拍等关键词，优先使用匹配笔记封面。此为标题筛选，不做视觉识别，不能保证封面内容或门店归属。没有匹配、下载失败或未配置小红书时显示餐具图标与“暂无菜品图片”，不再裁切固定参考图或使用风景图兜底。自动补全的泛用用餐安排不搜索图片。
- 独立 HTML 导出景点使用内嵌默认示意图，美食使用占位图，打开导出文件不触发小红书请求。不采集评论、视频或图片内文字，不自动写入百炼，不增加后台采集任务。行前刷新继续核实价格、开放和交通，不自动重采社区笔记。
- 使用 TripStar 固定版本的签名资源，生成相互关联的 `XYS_`、`x-t`、`x-s-common`；最新排序与 TripStar 一样通过 filters 指定。HTTP 浏览器标识与 JS 模拟环境统一为 Edge/Chrome 138。资源来源、固定版本及 GPL-2.0 许可证见 `travelmate/vendor/tripstar/NOTICE.md`、`LICENSE`，对外分发前需核对许可要求。
- 这仍是非官方网页接口。JS 引擎使用上游模拟环境，离线签名测试通过不代表小红书必定接受，更不保证账号不会退出。首次人工验收应使用可承担会话失效风险的测试账号，遇到拒绝立即停止。
