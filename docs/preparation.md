# 行前准备与旅行历史

项目已有 SQLite：账号、会话历史和方案版本都保存在 `DATABASE_PATH`（默认 `data/checkpoints.sqlite`）。本次复用原有工作流检查点保存清单，不引入额外数据库服务。

## 当前行为

- 自动生成清单每项对应一件物品或一个动作；旧版自动事项中的常见复合物品会拆成独立勾选项，沿用原完成状态，原提醒保留为可展开的准备说明。手动修改过的事项不自动拆分；超过100项时保留原项。

- 清单按证件、随身用品、出发确认展示，旧事项按关键词自动归类；新增时可选择分类并保存。支持全部、待准备、已完成筛选，总进度和分类计数始终统计完整清单。

- “行前准备”在导航中位于“每日行程”前，可勾选、新增、修改、删除；初始事项来自该版本攻略的行前提醒。
- 在线清单保存在服务器，沿用登录和会话归属检查。相同账号在不同设备打开同一会话、同一方案版本，可读取已保存的清单。
- 清单按会话和版本隔离，保存在工作流 `preparation_lists` 中，不改变原始方案快照，也不触发模型生成；修改行程产生新版本后，其清单独立初始化。
- 保存包含修订号；旧页面提交时如有冲突会返回409，不覆盖其他页面的修改。失败提示保留当前页面草稿，用户可重试，刷新前需注意尚未保存状态。
- 导出 Markdown/PDF/HTML 时使用服务器最新清单，准备模块排在每日行程前；勾选状态在 Markdown 中以 `[x]` / `[ ]` 表示。
- 下载的离线 HTML 可在当前浏览器勾选和编辑，通过 localStorage 保存。它与在线账号不自动同步，清理浏览器数据、换浏览器或换设备不会保留这份离线修改。浏览器存储不可用时会提示。
- 清单每版最多100项，每项1至500字。删除会话时，随会话检查点一起删除清单。

## 长期使用建议

个人或小团队阶段保留 SQLite 即可，重点是服务器使用持久磁盘/挂载 `data` 目录并定期备份。旅行历史继续通过现有会话与方案版本查看，不必为新增清单引入数据库产品。

浏览器存储适合离线副本，不适合作为旅行档案的唯一来源。若后续需要离线修改回传，应另行设计同步和冲突处理；若发展成多实例部署或大量并发编辑，再评估把旅行与清单迁移为独立业务表或使用 PostgreSQL。

轮播每4秒切换一次，仅在轮播区域离开视口、切换到其他板块或标签页进入后台时暂停；返回可见状态后继续。鼠标悬停、键盘焦点和手动切换不再暂停自动播放。系统“减少动态效果”仍关闭CSS过渡，不阻止定时切换。
